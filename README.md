# Приложение для чата в реальном времени (chat-app)

[![Версия Go](https://img.shields.io/badge/go-1.21+-blue.svg)](https://golang.org)
[![Лицензия: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

Этот проект представляет собой серверную часть для чата в реальном времени с разделением на комнаты. Он написан на Go и соответствует принципам чистой архитектуры. Для аутентификации пользователей он взаимодействует с отдельным сервисом `auth-service` через gRPC. Он поддерживает обмен сообщениями в реальном времени, отслеживание статуса доставки и уведомления о прочтении через WebSockets.

## Основные функции

-   **Архитектура микросервисов:** взаимодействует с отдельным `auth-сервисом` для надежной аутентификации пользователей и проверки токенов.
-   **Чат на основе комнат:**
    -   Создание новых чатов.
    -   Присоединение к существующим чатам, используя уникальный автоматически сгенерированный код приглашения.
    -   Просмотр списка всех чатов, в которых состоит пользователь.
-   **Обмен сообщениями в реальном времени:**
    - Доставка сообщений в реальном времени с помощью WebSockets.
    - Отправка сообщений всем подключённым участникам комнаты.
    - **Статус и история сообщений:**
    - **История сообщений:** при подключении пользователь получает последние 50 (n) сообщений из комнаты.
    - **Статус доставки:** отправители получают подтверждение (`✓`), что сервер сохранил их сообщение.
    -   **Уведомления о прочтении:** отправители получают уведомление в режиме реального времени (`✓✓`), когда другие пользователи получают и читают их сообщения.
-   **Синхронизация состояния:** включает механизм `повторной синхронизации`, позволяющий клиентам получать любые сообщения, пропущенные во время отключения.

## Архитектура

Сервис создан в соответствии с принципами **чистой архитектуры**, четким разделением задач, высокой согласованности и низкой связанности.

-   **Domain:** содержит основные бизнес-модели (`Комната`, `Сообщение`) и общекорпоративные бизнес-правила.
-   **UseCase:** реализует бизнес-логику для конкретного приложения, управляя потоком данных между доменом и репозиториями.
-   **Repository:** определяет интерфейсы для сохранения данных. Реализация (`/internal/repository/postgres`) обеспечивает взаимодействие с базой данных PostgreSQL.
-   **Delivery:** обеспечивает взаимодействие приложения с внешним миром. Сюда входит:
    - ** HTTP-доставка (`/internal/delivery/http`):** RESTful API на основе Gin для управления комнатами.
    - **WebSocket Delivery (`/внутренняя/доставка/ws`):** Реализация Gorilla WebSocket для обмена данными в режиме реального времени, управляемая центральным `hub-ом`.

## Стек технологий

- ** Язык интерфейса:** Go (Golang)
- **Платформа API:** [Gin](https://github.com/gin-gonic/gin) для HTTP-сервера.
-   **Связь в реальном времени:** [Gorilla WebSocket](https://github.com/gorilla/websocket) для подключения через WebSocket.
-   **База данных:** PostgreSQL, доступ к которой осуществляется через драйвер [pgx/v5](https://github.com/jackc/pgx).
-   **Взаимодействие между сервисами:** gRPC для аутентификации в `auth-service`.
-   **Логирование:** [slog](https://pkg.go.dev/log/slog) (стандартная библиотека) для структурированного ведения журнала, готового к использованию в продакшене.
-   **Конфигурация:** [godotenv](https://github.com/joho/godotenv) для управления переменными среды.
-   **Тестирование:**
    -   [testify](https://github.com/stretchr/testify) для утверждений и имитации.
    - [testcontainers-go](https://github.com/testcontainers/testcontainers-go) для надёжного интеграционного тестирования с использованием реальной базы данных PostgreSQL в Docker.

## Конечные точки API

Все конечные точки начинаются с `/api/v1`. Для всех конечных точек требуется аутентификация с использованием `Bearer <токен>`.

### HTTP API

| Метод | Конечная точка | Описание |
| :--- | :--- | :--- |
| `POST` | `/rooms` | Создает новую комнату чата. Пользователь, отправляющий запрос, становится ее владельцем. |
| `POST` | `/rooms/join` | Присоединяет пользователя к существующей комнате, используя `room_id` и `invite_code`. |
| `GET` | `/rooms` | Извлекает список всех комнат, в которых зарегистрирован пользователь. |

### WebSocket API

#### Подключение

- `GET /ws/:roomId`
    - Инициирует подключение через WebSocket к определенной комнате чата.
    - Аутентификация передается с помощью параметра запроса "токен": "ws://host/api/v1/ws/1?токен=<access_token>`.

#### Входящие сообщения (Клиент -> Сервер)

| Тип | Имя | Полезная нагрузка | Описание |
| :--- | :--- | :--- | :--- |
| 1 | `MsgSend` | `{ "text": "...", "client_msg_id": "..." }` | Отправляет новое сообщение в текущую комнату. |
| 7 | `MsgRead` | `{ "up_to_message_id": 123 }` | Информирует сервер о том, что клиент прочитал все сообщения до указанного идентификатора. |
| 8 | `MsgResync` | `{ "last_recv_message_id": 120 }` | Запрашивает все сообщения, отправленные с момента получения клиентом последнего известного идентификатора сообщения. |

#### Исходящие сообщения (сервер -> клиент)

| Тип | Имя | Полезная нагрузка | Описание |
| :--- | :--- | :--- | :--- |
| 2 | `MsgMessage` | Текст сообщения. | Новое сообщение, отправленное всем участникам комнаты. |
| 10 | `MsgHistory` | Текст сообщения. | Одно сообщение из истории комнаты, отправленное при подключении. |
| 5 | `MsgAck` | `N/A` | Подтверждает отправителю, что его сообщение было успешно сохранено. |
| 7 | `MsgRead` | `N/A` | Информирует отправителя о том, что другой пользователь прочитал его сообщение (сообщения). |

## Начало работы

### Необходимые условия

-   Go 1.21+
-   PostgreSQL
-   Docker (для запуска тестов)
-   Работающий экземпляр `auth-service`.

### Установка и настройка

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/Kovalyovv/chat-app.git
    cd chat-app
    ```

2.  **Установите зависимости:**
    ```bash
    go mod tidy
    ```

3.  **Настройте среду:**
    Создайте файл `.env` в корне проекта и добавьте необходимые переменные.

    ```env
    # Порт для HTTP-сервера и сервера WebSocket чат-приложения
    API_PORT=8080

    # Строка подключения к базе данных PostgreSQL
    DB_URL=postgres://user:password@localhost:5432/chat_db?sslmode=disable

    # Адрес работающего сервера gRPC службы аутентификации
    AUTH_SERVICE_ADDR=localhost:50001
    ```

### Запуск службы

Запустите основное приложение:
```bash
go run cmd/api/main.go
```
Сервер запустится и выведет в журнал сообщение о том, что он прослушивает указанный порт.

## Запуск тестов

Проект включает в себя комплексный набор интеграционных тестов для хаба WebSocket.

Чтобы запустить все тесты, выполните следующую команду из корневого каталога:
```bash
go test -v ./...
```

Основной тест, `TestHub_FullFlow_Delivery_Read_Resync`, использует `testcontainers-go` для автоматического запуска временного контейнера PostgreSQL Docker. Он проверяет полный жизненный цикл соединения WebSocket, включая:
- Отправку и получение сообщений между двумя клиентами.
- Проверяет, обновлено ли состояние доставки сообщений в базе данных.
- Подтверждает, что события "MsgRead" передаются правильно.
- Тестирование повторного подключения клиента и логики "повторной синхронизации".
